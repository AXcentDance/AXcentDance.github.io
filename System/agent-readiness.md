## What still needs the owner (blocked on infrastructure / off-site)

### A. Markdown content negotiation (acceptmarkdown.com) — needs an edge layer

The acceptmarkdown.com convention requires, on the SAME URL:

- `Accept: text/markdown` returns markdown with
  `Content-Type: text/markdown; charset=utf-8`
- every negotiated response carries `Vary: Accept`
- unsupported `Accept` types get `406 Not Acceptable`
- q-values are honored

GitHub Pages cannot set headers or branch on the `Accept` header, so this is
impossible on the current stack alone. The `.md` twins above are the data
source; what is missing is a thin proxy in front of GitHub Pages.

Cheapest path: move DNS for axcentdance.com behind Cloudflare (free plan) and
deploy `System/cloudflare/markdown-negotiation-worker.js` as a Worker on the
zone with a route for `axcentdance.com/*`. Steps:

1. Add the site to a Cloudflare account (free plan), let it import DNS
   records, and switch the nameservers at Namecheap to the two Cloudflare
   ones. Keep the four GitHub Pages A records (185.199.108-111.153) and the
   CNAME behavior exactly as imported; enable "Full (strict)" TLS.
2. Workers & Pages -> create Worker -> paste the worker file -> deploy.
3. Add a Worker route: `axcentdance.com/*` (and `www.axcentdance.com/*`).
4. Verify (all four spec checks):

   ```
   curl -sI -H "Accept: text/markdown" https://axcentdance.com/schedule | grep -iE "content-type|vary"
   curl -sI https://axcentdance.com/schedule | grep -i vary
   curl -s -o /dev/null -w "%{http_code}" -H "Accept: application/json" https://axcentdance.com/schedule
   curl -sI -H "Accept: text/markdown;q=0.2, text/html;q=0.9" https://axcentdance.com/schedule | grep -i content-type
   ```

   Expected: markdown + `Vary: Accept`; `Vary: Accept` on the HTML variant
   too; `406`; `text/html`.

Nothing else about hosting changes: GitHub Pages remains the origin and the
deploy flow (push to main) stays identical.
